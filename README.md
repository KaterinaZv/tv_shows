# TV Shows Explorer

Поиск сериалов через [TVmaze API](https://www.tvmaze.com/api) с фильтром по жанрам, пагинацией и избранным. Учебный проект для отработки **Simple Architecture** — правила описаны в [ARCHITECTURE.md](ARCHITECTURE.md).

- **Приложение:** https://katerinazv.github.io/tv_shows/
- **API:** https://tv-shows-api-6w33.onrender.com/api/health

> ⏳ API работает на бесплатном тарифе Render: после 15 минут без запросов сервер засыпает, и первый поиск после этого занимает до минуты. При засыпании и перезапуске **данные в памяти (кеш, сессии и избранное) стираются**: придётся войти заново — баз данных в проекте пока нет.

## Возможности

- Поиск сериалов по названию: debounce 400 мс, отмена устаревших запросов.
- Фильтр по жанрам из текущей выдачи — несколько жанров сразу (логика «ИЛИ»), сброс через «Все жанры».
- Пагинация по 3 сериала на страницу.
- Вход по email без пароля: отдельная страница `#/login`, email и кнопка «Выйти» в шапке. Сессия сохраняется после перезагрузки страницы.
- Избранное у каждого пользователя своё: звёздочка на карточке, toast-уведомление при добавлении и удалении, кнопка со счётчиком и панель со списком. Гость может искать и смотреть сериалы, а звёздочка отправляет его на страницу входа. После выхода и повторного входа под тем же email избранное на месте.
- Кеширование запросов к TVmaze на сервере на 5 минут.
- Состояния загрузки, пустой выдачи, ошибок, офлайна и таймаута.
- RU / EN, тёмная и светлая тема по системной настройке, mobile first.

## Кто за что отвечает

| Backend (`server/`) — источник истины                | Frontend (`client/`) — отображение и ввод                  |
| ---------------------------------------------------- | ---------------------------------------------------------- |
| Запросы к TVmaze и их кеширование (5 минут)          | Поле поиска, debounce, выбранные жанры и страница          |
| Фильтрация по жанрам и пагинация                     | Отправка параметров на `/api/shows` и показ ответа         |
| Сессии: вход по email, проверка токена, выход        | Страница входа, токен в `localStorage`, email в шапке      |
| Хранение избранного и правила его изменения          | Звёздочка, toast, счётчик, панель избранного               |
| Валидация входных данных, перевод ошибок в HTTP-коды | Тексты (i18n), форматирование, состояния загрузки и ошибок |

Фронтенд не обращается к TVmaze напрямую и не дублирует фильтрацию и пагинацию.

## Архитектура

Simple Architecture — вариант VIPER для React:

| Слой      | Frontend                                          | Backend                                           |
| --------- | ------------------------------------------------- | ------------------------------------------------- |
| View      | Компонент — только JSX                            | —                                                 |
| Presenter | Хук `logic/usePresenter.ts`                       | `routes.ts` — разбор запроса и HTTP-ответ         |
| Tasks     | `logic/tasks/`, `src/tasks/` — сценарии           | `modules/*/tasks/`, `src/tasks/` — бизнес-логика  |
| Entity    | Сторы (`createStore`, get / set), кеш React Query | Объекты в памяти: `cache`, `sessions`, `favorite` |
| DAL       | `api/httpClient.ts` → наш API                     | `dal/createHttpClient.ts` → TVmaze                |

Правила проверяются автоматически: ESLint (слои, импорты, `any`, сырые HTML-элементы вне ui-kit), Stylelint (mobile first), Prettier и git-хуки.

## Структура

```
client/   ← React + TypeScript + Vite + React Query + React Router + i18next (GitHub Pages)
server/   ← Node.js + TypeScript + Express (Render)
shared/   ← типы контракта API, общие для client и server
```

## API

Вход — по email без пароля. `POST /api/auth/login` возвращает токен сессии; клиент хранит его в `localStorage` и отправляет в заголовке `Authorization: Bearer <token>`. Без токена запросы идут от гостя: поиск работает, у всех сериалов `isFavorite: false`, а `/api/favorites` отвечает `401`.

| Метод    | Путь                          | Описание                                                               |
| -------- | ----------------------------- | ---------------------------------------------------------------------- |
| `GET`    | `/api/health`                 | Проверка, что сервер жив                                               |
| `POST`   | `/api/auth/login`             | Вход: тело `{ "email": "me@example.com" }`, ответ `{ user, token }`    |
| `GET`    | `/api/auth/me`                | Текущий пользователь: `{ user }`, `user: null` для гостя               |
| `POST`   | `/api/auth/logout`            | Выход: закрывает сессию, ответ `204`                                   |
| `GET`    | `/api/shows?q=&genres=&page=` | Поиск: `q` — запрос, `genres` — жанры через запятую, `page` — страница |
| `GET`    | `/api/favorites`              | Избранное пользователя, последние добавленные сверху (нужен вход)      |
| `POST`   | `/api/favorites/:showId`      | Добавить сериал в избранное (данные сервер берёт из TVmaze сам)        |
| `DELETE` | `/api/favorites/:showId`      | Убрать сериал из избранного                                            |

Пример ответа `GET /api/shows?q=murder&genres=Comedy,Medical` (поля сериала сокращены):

```json
{
  "items": [
    { "id": 3307, "name": "Diagnosis: Murder", "genres": ["Drama", "Crime", "Medical"], "isFavorite": false },
    { "id": 57586, "name": "Murder Mystery", "genres": ["Comedy", "Action", "Crime"], "isFavorite": false }
  ],
  "genres": ["Action", "Comedy", "Crime", "Drama", "Legal", "Medical", "Mystery"],
  "total": 10,
  "filteredTotal": 2,
  "page": 1,
  "pageSize": 3,
  "totalPages": 1
}
```

Ошибки: `400` — неверные параметры или email, `401` — нужен вход, `404` — сериал не найден, `429` — TVmaze просит подождать, `502` — TVmaze недоступен, `504` — TVmaze не ответил вовремя.

## Кеширование

- **Сервер:** любой запрос к TVmaze (поиск, данные сериала) кешируется в памяти на 5 минут. Тот же запрос в течение этого времени — от любого пользователя — в TVmaze не уходит. В логах сервера видно `[cache] miss` / `[cache] hit`.
- **Клиент:** React Query кеширует ответы нашего API в рамках вкладки; после добавления в избранное кеш обновляется по ответу сервера, без повторных запросов.

## Запуск локально

Нужен Node.js 20.19+.

```bash
npm install
npm run dev
```

Клиент — http://localhost:5173, API — http://localhost:3000. Запросы клиента к `/api` проксируются на сервер через Vite.

| Команда         | Что делает                        |
| --------------- | --------------------------------- |
| `npm run dev`   | Клиент и сервер вместе            |
| `npm run check` | Типы, ESLint, Stylelint, Prettier |
| `npm run build` | Сборка клиента и сервера          |

## Деплой

- **Клиент:** push в `main` → GitHub Actions собирает `client/` с переменной `VITE_API_URL` и публикует на GitHub Pages.
- **Сервер:** Render по `render.yaml` пересобирает сервис при изменениях в `server/`, `shared/` или зависимостях.
